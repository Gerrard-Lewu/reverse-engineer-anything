Current phase: planning and reference investigation. The user explicitly requested continued Plan mode; the application build has not started. S0–S2 describe planning/investigation work. S3 is the first future application implementation slice and begins only when the user moves the task into the build phase.

## Delivery goal

Deliver a source-compared, privately hosted cloud lead-to-meeting tool with a Ceverio profile, independent sourcing/CSV, explainable qualification, bounded autonomous messaging, a synced inbox, booking links/outcomes, and usable recovery. Windows is the owner browser; inference and the worker need not run on the laptop. Prepare 30 qualified companies and a five-prospect pilot once a permitted sender and all readiness gates exist. Validate the complete journey with controlled accounts before unattended prospect operation.

Development is spec driven. Every slice names its requirements, implements meaningful acceptance tests before its behavior, and records verification at the level actually reached. Fixture success, provider acceptance, recipient delivery and visual comparison remain separate outcomes.

## Verification and change discipline

- Use Given/When/Then scenarios to verify user-visible behavior and consequential recovery, not implementation mirrors.
- Inject clock/provider failures for ambiguous external effects, leases, cursor replay, paid starts and restore. Verify database semantics against PostgreSQL.
- Use captured generic/source-state fixtures for rendering; do not commit actual contact/inbox material.
- Pin dependencies/lockfiles and preserve reproducible migrations. Use the actual Supabase CLI help/schema when creating migration files or calling MCP.
- Record per-slice requirement IDs, changed implementation paths, test bindings/commands/results, source/provider evidence and remaining gaps.
- Once a slice's required checks pass, move to the next unblocked slice; repeat checks only after relevant changes/failures.
- No milestone is “live verified” solely because a mocked adapter passes, a server starts or a UI looks plausible.
